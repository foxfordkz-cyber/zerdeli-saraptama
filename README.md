# Zerdeli Сараптама

Сайт для экспертизы проектов программ Zerdeli Group (2026–2027 учебный год).

[Открыть каталог](https://zerdeli-saraptama.pages.dev/) · [Кабинет руководителя](https://zerdeli-saraptama.pages.dev/#/admin) · [Зеркало на GitHub Pages](https://foxfordkz-cyber.github.io/zerdeli-saraptama/)

- **Эксперт** заходит без регистрации. Он открывает документ и читает его прямо в браузере, в том числе с телефона. Затем вводит имя, фамилию и школу и оставляет комментарий голосом (до 5 минут) или текстом, можно к конкретному разделу.
- **Руководитель** нажимает «Кабинет руководителя» в шапке сайта («Кабинет» на телефоне) и входит по почте и паролю. Там он слушает и читает все комментарии, фильтрует их по направлению, документу, школе и типу, отмечает просмотренные и выгружает список в Excel.
- **Другие эксперты чужих комментариев не видят.** Это ограничение работает на уровне базы данных (row-level security), а не только в интерфейсе.

На сайте 67 документов по 22 направлениям: 54 Word, 9 PDF и 4 Excel-плана для 1–11 классов. В каталог от 17 ноября 2026 года включена редакция концепции образования и личностного развития от 20 ноября. Её можно [прочитать в браузере](https://zerdeli-saraptama.pages.dev/#/doc/education-system) или скачать со страницы документа.

Интерфейс полностью доступен на казахском и русском через переключатель **ҚАЗ / РУС**; выбор сохраняется в браузере. Тексты документов и названия их внутренних разделов остаются на языке оригинала.

Каталог фильтруется по направлению, классу, типу и формату; поиск понимает оба языка, а фильтры сохраняются при возвращении из документа. В просмотре доступны широкий режим чтения, ссылки на конкретные разделы и открытие оригинального PDF для увеличения и печати. Мобильная форма поддерживает управление с клавиатуры и остаётся открытой во время записи голоса.

Общие документы идут первыми: `01…` обозначен как I бөлім, `00005…` — II–V бөлімдер. Оба файла представлены целиком, с исходной внутренней нумерацией. Все папки `черновик` исключены; промежуточные редакции системы из `123` и два текстовых дубля английского для 2 класса не дублируются. Новая программа домбры 1–9 заменяет прежние материалы 1–4; комментарии к старому приложению остаются в кабинете как архивные. PDF из `NUET_PDF.zip` включён отдельным руководством. Ключи, сертификаты и прочие служебные файлы не импортируются.

## Как это устроено

| Часть | Технология |
|---|---|
| Сайт | React + Vite, статический сайт на Cloudflare Pages и GitHub Pages. Оба адреса используют один проект Supabase |
| Документы | `.docx` превращаются в HTML (mammoth); PDF показаны страницами оригинала с раскрываемым текстом; Excel — таблицами с объединёнными ячейками. Все оригиналы доступны для скачивания |
| Комментарии | Supabase (Postgres), таблица `comments` |
| Аудио | Supabase Storage, приватный бакет `comment-audio` |
| Доступ | RLS: аноним может только добавить запись; читать, менять и удалять может только почта из таблицы `admins` |

Пока ключи Supabase не указаны, сайт работает в **демо-режиме**: комментарии сохраняются только в текущем браузере, а в кабинет можно войти без пароля. Так можно всё проверить до подключения базы.

Кабинет загружает все комментарии порциями, показывает ошибки операций и выгружает полный отфильтрованный список в CSV для Excel. Текстовые ячейки защищены от исполнения формул. Ссылка из отзыва ведёт к его разделу, если он ещё присутствует в документе.

При обрыве сети после загрузки аудио файл может остаться без записи комментария. Клиент не удаляет аудио после неоднозначного результата сохранения, чтобы не потерять успешно принятый отзыв. Для рабочего Supabase нужна периодическая серверная очистка старых файлов без связанных комментариев; анонимное удаление из приватного бакета не разрешается.

## Подключение Supabase (около 10 минут)

1. Зарегистрируйтесь на <https://supabase.com> и создайте проект (**New project**). Регион выберите ближайший, например Frankfurt.
2. Откройте **SQL Editor → New query**, вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
3. **Authentication → Users → Add user → Create new user**: укажите почту и пароль руководителя и включите **Auto Confirm User**.
4. В SQL Editor выполните запрос, подставив эту почту:
   ```sql
   insert into public.admins (email)
   select lower(email) from auth.users
   where lower(email) = lower('boss@example.com')
     and email_confirmed_at is not null and deleted_at is null
   on conflict (email) do nothing;
   ```
5. **Authentication → Sign In / Providers**: выключите **Allow new users to sign up**. Новые аккаунты сможет создавать только администратор.
6. **Project Settings → API**: скопируйте **Project URL** и **Publishable key** (в старых проектах он называется `anon public`).
7. Передайте эти два значения сайту одним из способов:
   - GitHub → **Settings → Secrets and variables → Actions → Variables**: добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY`;
   - или создайте в репозитории файл `.env.production` по образцу [`.env.example`](.env.example).

   Оба значения публичные по задумке Supabase. Защиту обеспечивают правила из `schema.sql`, а не секретность ключа. Секретный ключ `service_role` никуда не вставляйте.

Если после входа сайт показывает адрес аккаунта и предлагает проверить доступ, владельцу проекта нужно проверить `public.admins` для этого адреса. После назначения прав руководитель нажимает «Проверить доступ» в открытом кабинете. Кнопка «Сменить аккаунт» завершает текущий сеанс и открывает форму входа.

## Публикация на Cloudflare Pages

Проект `zerdeli-saraptama` использует Direct Upload. Для обновления основного адреса войдите в Wrangler под аккаунтом проекта и опубликуйте готовую сборку в его рабочую ветку:

```bash
npm ci
npm test
npm run build
npx wrangler@4 pages deploy dist --project-name zerdeli-saraptama --branch claude/modest-cannon-cz97bd
```

GitHub Actions отдельно обновляет зеркало при изменении основной ветки.

## Публикация на GitHub Pages

1. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
2. Каждый push собирает сайт. Публикуется только ветка по умолчанию.
3. Адрес сайта: `https://<владелец>.github.io/<репозиторий>/`. Для этого репозитория это <https://foxfordkz-cyber.github.io/zerdeli-saraptama/>.
4. Ссылку для школ можно скопировать в кабинете кнопкой «Сілтемені көшіру».

Перезапустить сборку вручную можно так: **Actions → Build and deploy → Run workflow**.

## Как обновить документы

1. Положите файл в `content/docs/<id>.docx`. `<id>` пишется латиницей, например `english-2`.
2. Добавьте запись в [`content/catalog.json`](content/catalog.json): направление, тип (`program` / `appendix` / `concept`), класс, язык, название на казахском и русском.
3. Сделайте push. Сайт пересоберётся сам.

Для PDF и XLSX укажите `format` и храните исходник в `content/docs/<id>.<format>`. Их подготовленный HTML, изображения страниц и SHA-256 исходника находятся в `content/extracted/` и входят в репозиторий. Сборка проверяет соответствие исходника и подготовленной версии, поэтому CI требует только Node.js.

Чтобы заново извлечь дополнительные материалы, используйте Python из bundled workspace runtime с `pdfplumber`, `pypdfium2`, `Pillow`, `openpyxl`:

```bash
python scripts/prepare-supplemental.py --source-root C:/ulan --content-dir content
```

Для нового PDF/XLSX сначала добавьте его описание в импортёр, затем перенесите запись из `.work/supplemental-catalog.json` в основной каталог. Поля `grade` и `load` могут быть `null` для общих документов; `part` задаёт обозначение разделов системы. Исходные документы не изменяются.

Автоматические проверки содержимого, фильтров, маршрутов, жизненного цикла аудио, API и экспорта запускаются перед сборкой в CI. Локально:

```bash
npm test
npm run build
```

## Структура

```
content/            исходные DOCX/PDF/XLSX, подготовленные представления и каталог
scripts/            импорт, конвертация в HTML и проверки содержимого
supabase/schema.sql таблицы, правила доступа, бакет для аудио
src/pages/          каталог, документ, кабинет руководителя
src/components/     форма комментария, запись голоса, плеер
```
