# Zerdeli Сараптама

Сайт для экспертизы проектов программ Zerdeli Group (2026–2027 учебный год).

- **Эксперт** заходит без регистрации. Он открывает документ и читает его прямо в браузере, в том числе с телефона. Затем вводит имя, фамилию и школу и оставляет комментарий голосом (до 5 минут) или текстом, можно к конкретному разделу.
- **Руководитель** входит в кабинет (`#/admin`) по почте и паролю. Там он слушает и читает все комментарии, фильтрует их по направлению, документу, школе и типу, отмечает просмотренные и выгружает список в Excel.
- **Другие эксперты чужих комментариев не видят.** Это ограничение работает на уровне базы данных (row-level security), а не только в интерфейсе.

На сайте 41 документ по 10 направлениям. Черновики (`арт студия/черновик`) не включены. Дубли основной программы английского языка для 2 класса тоже не включены: файлы `ағылшын 2 сынып.docx` и `Zerdeli_English_2_klass_osnovnoy_fayl_RU.docx` по тексту совпадают с приложениями.

## Как это устроено

| Часть | Технология |
|---|---|
| Сайт | React + Vite, статический, хостинг GitHub Pages |
| Документы | `.docx` при сборке превращаются в HTML (mammoth); оригинал можно скачать |
| Комментарии | Supabase (Postgres), таблица `comments` |
| Аудио | Supabase Storage, приватный бакет `comment-audio` |
| Доступ | RLS: аноним может только добавить запись; читать, менять и удалять может только почта из таблицы `admins` |

Пока ключи Supabase не указаны, сайт работает в **демо-режиме**: комментарии сохраняются только в текущем браузере, а в кабинет можно войти без пароля. Так можно всё проверить до подключения базы.

## Подключение Supabase (около 10 минут)

1. Зарегистрируйтесь на <https://supabase.com> и создайте проект (**New project**). Регион выберите ближайший, например Frankfurt.
2. Откройте **SQL Editor → New query**, вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
3. **Authentication → Users → Add user → Create new user**: укажите почту и пароль руководителя и включите **Auto Confirm User**.
4. В SQL Editor выполните запрос, подставив эту почту:
   ```sql
   insert into public.admins (email) values (lower('boss@example.com'));
   ```
5. **Authentication → Sign In / Providers**: выключите **Allow new users to sign up**. Новые аккаунты сможет создавать только администратор.
6. **Project Settings → API**: скопируйте **Project URL** и **Publishable key** (в старых проектах он называется `anon public`).
7. Передайте эти два значения сайту одним из способов:
   - GitHub → **Settings → Secrets and variables → Actions → Variables**: добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY`;
   - или создайте в репозитории файл `.env.production` по образцу [`.env.example`](.env.example).

   Оба значения публичные по задумке Supabase. Защиту обеспечивают правила из `schema.sql`, а не секретность ключа. Секретный ключ `service_role` никуда не вставляйте.

## Публикация на GitHub Pages

1. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
2. Каждый push собирает сайт. Публикуется только ветка по умолчанию.
3. Адрес сайта: `https://<владелец>.github.io/<репозиторий>/`. Для этого репозитория это `https://foxfordkz-cyber.github.io/zerdelikov/`.
4. Ссылку для школ можно скопировать в кабинете кнопкой «Сілтемені көшіру».

Перезапустить сборку вручную можно так: **Actions → Build and deploy → Run workflow**.

## Как обновить документы

1. Положите файл в `content/docs/<id>.docx`. `<id>` пишется латиницей, например `english-2`.
2. Добавьте запись в [`content/catalog.json`](content/catalog.json): направление, тип (`program` / `appendix` / `concept`), класс, язык, название на казахском и русском.
3. Сделайте push. Сайт пересоберётся сам.

```

scripts/            конвертация .docx → HTML и списка разделов

src/pages/          каталог, документ, кабинет руководителя
src/components/     форма комментария, запись голоса, плеер
```
